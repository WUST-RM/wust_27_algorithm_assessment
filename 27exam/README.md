### TASK3

- 题目背景：哨兵是战场上唯一能自主行动的机器人，它要在场地里自己找路：去占领增益点，受到威胁时撤回基地。小祥负责哨兵的导航，先把场地离散成一张栅格地图：墙和障碍物不能通过，空地正常通行，减速带则会拖慢哨兵，通过一格的代价更高。导航需要回答两类问题。一类是"能不能到"：目标点是不是被障碍物围住了，哨兵最多能到达多大的区域？这类问题可以使用深度优先搜索（DFS），把能走到的格子都遍历一遍即可。另一类是"怎么走最省"：从当前位置到目标点，代价最小的路线是哪条？这类问题可以使用 A* 算法：它在每一步优先扩展"已经付出的代价加上预计剩余代价"最小的格子，比盲目搜索快得多。如果目标根本到不了，A* 会把整片区域搜一遍才能得出结论，所以应该先用 DFS 判断是否可达。请你帮小祥把这两个算法实现出来。
- 题目：在 TASK3 目录下新建 `main.cpp`，编写程序从标准输入读取地图，输出可达区域的信息和最小代价。

输入格式：
- 第一行是两个整数 R、C（2 ≤ R, C ≤ 100），表示地图的行数和列数。
- 接下来 R 行，每行 C 个字符，表示地图，不含空格：
  - `#`：障碍物，不能进入；
  - `.`：空地，进入的代价为 1；
  - `2`~`9`：减速带，进入这一格的代价就是这个数字；
  - `S`：起点，恰好一个；
  - `G`：终点，恰好一个，进入的代价为 1。

移动规则：每一步只能走到上、下、左、右相邻的格子，不能斜着走，不能走出地图，不能进入障碍物。一条路线的代价是它依次进入的所有格子的代价之和，起点不计入；若路线中途再次进入 S，按空地计，代价为 1。

需要输出三项：
1. `reachable_cells`：从起点出发能走到的格子数，包含起点本身。用 DFS 求。
2. `regions`：整张地图中，彼此不连通的可通行区域有几块。起点所在的区域也算一块。用 DFS 求。
3. `cost`：从起点到终点的最小代价。如果到不了，输出 -1。用 A* 求，启发函数用到终点的曼哈顿距离（行差的绝对值加列差的绝对值）。

输出格式：

```
reachable_cells: 43
regions: 2
cost: 17
```

样例输入：

```
7 10
S..#......
.#.#.####.
.#...#....
.###.#.##.
.333333..G
.#######.#
...#..#...
```

样例输出：

```
reachable_cells: 43
regions: 2
cost: 17
```

样例说明：地图一共有 45 个可通行格子。最后一行中间的两个格子（第 5、6 列）被障碍物围住，从起点到不了，所以 `reachable_cells` 是 43，`regions` 是 2。从 S 到 G，步数最少的路线是 13 步，但要穿过减速带，代价至少是 19；最小代价的路线绕过去，要走 17 步，全是空地，代价是 17。所以最小代价是 17，不是步数最少的那条。

要求：
1. 可达格子数和区域数可以用 DFS 求，最小代价可以用 A* 求。
2. 输出必须与样例的格式逐字符一致，不得输出多余内容。
3. 验收标准：样例输出完全一致。可以自己随意实现输入地图，检查输出测试算法。

- 考察内容：二维数组与 `std::vector` 的使用；递归（或显式栈）实现 DFS；`std::priority_queue` 与自定义比较；A* 的基本思想（已付出的代价加启发函数）。
- 提示：
  - 别见到新名词就怕，去网上简单查一下DFS和A*的思路几行代码就能写出来。（你看我下面写这么多提示）
  - 除了用A*算法之外，也可以尝试Dijkstra、BFS等算法以及各种变体，可以自己灵活实现。
  - 用 `dr[4] = {-1, 0, 1, 0}`、`dc[4] = {0, 1, 0, -1}` 两个数组表示四个方向，循环处理邻居，不要把四个方向的代码各抄一遍。
  - DFS 先写一个能走到相邻格子的函数，递归调用自己，用一个 `visited` 数组避免重复访问。
  - A* 的优先队列里放的是 `f = g + h`：`g` 是已经付出的代价，`h` 是曼哈顿距离。`std::priority_queue` 默认是大顶堆，要让 f 最小的先出来，需要自定义比较，或者存负数。
  - 一个格子可能先后以不同的代价被放进队列，需要记录每个格子目前已知的最小 `g`，弹出来的队列项如果比记录的更差，就直接跳过。
  - 曼哈顿距离不会高估剩余代价，因为每一步的代价至少是 1，所以 A* 一定能找到最小代价。如果把 `h` 乘以 2，就可能找到的路线不是最优。

### TASK4

- 题目背景：小博在重构自瞄的预处理模块时发现，该模块要处理三种来源的图像：相机直出的帧、ROS 话题里带行填充的图像、视频文件解码出的 YUV 帧。原来的写法用虚函数 `at(x, y)` 统一读取像素，一帧 1280×1024 的图像要做一百多万次虚函数调用，编译器既不能内联，也不能向量化，预处理成了瓶颈。他想改用模板：图像来源的类型在编译期就是已知的，可以在编译期为每种来源选好各自的取像素方式，运行期不留任何开销，实现零开销抽象。请你帮他实现虚函数版本和模板版本。
- 题目：给定三种图像来源的原始数据结构（均为单通道 8 位图像）：

```cpp
struct CameraFrame { int w, h; const unsigned char* buf; };
struct RosImage    { int w, h, step; const unsigned char* data; };  // step 为每行字节数，step >= w
struct VideoFrame  { int w, h; const unsigned char* yuv; };         // 只使用前 w*h 字节（Y 平面）
```

三种来源的像素访问语义：
- 相机帧：零拷贝，像素 (x, y) 为 `buf[y*w + x]`；
- ROS 图像：像素 (x, y) 为 `data[y*step + x]`，每行末尾的 padding 不参与计算；
- 视频帧：Y 值通常在 16~235 之间（测试数据可能越界）；统一按 `max(yuv[y*w + x] - 16, 0)` 计算，即低于 16 的当作 0，不做上限钳位。

预处理算法：按行优先遍历所有像素，逐像素取值并用 `std::uint64_t` 累加，返回累加和。两个版本的遍历循环写法一致，它们只在"怎样取一个像素"上不同。

虚函数版本API（放在 `namespace virt` 中）：

```cpp
namespace virt {
class ImageSource {
public:
    virtual ~ImageSource() = default;
    virtual int width() const = 0;
    virtual int height() const = 0;
    virtual unsigned char at(int x, int y) const = 0;
};

class CameraSource : public ImageSource { public: explicit CameraSource(CameraFrame f); /* 实现三个虚函数 */ };
class RosSource    : public ImageSource { public: explicit RosSource(RosImage f);       /* 同上 */ };
class VideoSource  : public ImageSource { public: explicit VideoSource(VideoFrame f);   /* 同上 */ };

std::uint64_t preprocess(const ImageSource& src);
}
```

模板版本API（放在 `namespace tmpl` 中）：

```cpp
namespace tmpl {
// Frame 为 CameraFrame、RosImage、VideoFrame 之一，直接使用上面的原始结构体，不需要再包装成类
template <typename Frame>
std::uint64_t preprocess(const Frame& f);
}
```

要求：完整实现 `virt` 和 `tmpl` 两套 API；对同一帧，两个版本的累加结果相同。

- 考察内容：虚函数与模板的实现机制和取舍；零开销抽象；熟练编写CMakeLists。
- 提示：三个结构体的成员名各不相同：`CameraFrame` 只有 `buf`，`RosImage` 有 `data` 和 `step`，`VideoFrame` 有 `yuv`。普通的 `if` 要求所有分支都能通过编译，写 `f.data` 时 `CameraFrame` 就会报错；`if constexpr` 在模板里会丢弃不满足条件的分支，不去编译它。

### TASK6
